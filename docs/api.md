# The service API

The window talks to one Go service, `BoardService`, with bound methods and events. The Wails bindings are generated by `wails3 generate bindings`.

## Methods

| Group | Methods |
|---|---|
| Start and settings | `Start`, `Info`, `Settings`, `Reconnect`, `SetDisplayName`, `SetShowInNotch`, `SetNotchPreview` |
| The board | `Board`, `MarkSeen`, `CreateBoard`, `JoinBoard`, `LeaveBoard`, `RenameBoard` |
| Columns and cards | `AddColumn`, `RenameColumn`, `MoveColumn`, `DeleteColumn`, `AddCard`, `EditCard`, `MoveCard`, `DeleteCard` |
| People | `RemoveMember`, `CreateInvite`, `Invites`, `RevokeInvite`, `ApproveRequest`, `DenyRequest` |
| History | `Activity` |
| Notch and tray | `Notch`, `NotchShow`, `NotchHide`, `NotchOpenApp` |

`CreateInvite` and `JoinBoard` work only from the main window: they are the only calls that carry an invite code.

`Board.leave` says what `LeaveBoard` does now (`everyone`, `alone`, `not-admin`, `local`, `removed`, `cancel`, or the refused `last-admin` and `last-settler`), so the window can say it before the person confirms. `Board.sync.stuck` is set when this member's own changes stayed unsettled for a minute while enough settlers were connected.

## Events

`board:state` (the whole board, at most ten a second), `board:network`, `board:change` (one change by another member) and `board:invites` go to the main window only. `board:notch` goes to the notch window only.

A snapshot can arrive after a newer event: the answer of `Start` after a `board:network` event, of `Board`, `CreateBoard` or `JoinBoard` after a `board:state` event. `Network` and `Board` carry a `seq` that grows with every state and every read, so the window keeps the one with the larger `seq`. The invites and the notch have no `seq`: every change sends `board:invites` or `board:notch`, so the window drops an answer of `Invites` or `Notch` when such an event arrived while it was asked for.

## The network

`Settings.mode` and `Network.mode` say which network the example is on: `public` (the default), `own` (`-bootstrap` or `-first`) or `local` (`-local`, this computer only). `Settings.entryNodes` is the comma list of the entry nodes of your own network (empty in `public`, where the window does not list the public entry nodes, and in `local`) and `Settings.entryNodesFrom` is where it came from: `public`, `flag`, `env`, `first` or `local`. `localNode` is the address of `-local` (`127.0.0.1:7451`) and `firstNode` the entry node this example runs itself, in `-local` only when it was the first window; both are empty elsewhere. `Network.state` is `starting`, `ready` or `failed`; a `failed` network has an `error` whose `reason` is `public-unreachable`, `bootstrap-failed`, `local-port-taken` or `first-node-failed`, and its message names the other networks. The example never changes network by itself.

## Connection relays

`Settings.connectionRelays` is the relay list as `host:port@key`, comma separated, and `Settings.connectionRelaysFrom` is where it came from: `flag`, `file`, `flag-and-file`, `env` or `none`. `Network.relays` lists each relay (never null) with its `addr`, its `key` in hex, its `state` and, when it failed, an `error`:

- `waiting`: used to reach others; the example holds a place there only while it has a board on the network;
- `ready`: it holds a place, so members who cannot connect directly reach this one through it;
- `failed`: `error.reason` is `relay-wrong-key` (it answered with another key, from the swarm or from the key check at start), `relay-bad-key`, `relay-not-allowed`, `relay-full` or `relay-unreachable`.

The routine end of a place, which kolo-swarm takes again at once, sends no event. A join that found nobody while relays are listed ends with `inviter-not-found-relays`.

## Errors

`ReportError(text)` writes an error of a window to the log (`frontend error: ...`), cleaned and cut to 8,192 characters: the window sends the error's message and stack only, never board text or keys. Both windows may call it.

Every error is a `BoardError` with a stable `reason`, a `kind`, a `detail`, a `cause` and an English `message`, so a window in another language translates by `reason`.
